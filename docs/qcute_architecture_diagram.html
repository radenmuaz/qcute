qcute_v1 — StackDecoder

How a cascading code decoder turns bytes into layered codes, and layered codes back into bytes

A walkthrough of two related architectures — ks21 (two levels) and ks221 (three levels) — using one running example, the 8 byte string the_cats. Same grammar throughout: solid arcs are self-attention inside one level, teal arrows are a level extracting its own code, ochre dashed arrows are decode cross-attending back to a code.

Figure A

ks21 — two levels

Level 0 reads raw bytes. Level 1 is the top — it reads level 0's own code as its input sequence, and nothing sits above it.

Reading bottom to top: level 0's encoder self-attends causally over the 8 bytes of the_cats and, at the end of every 2-byte block, extracts one discrete code (c1..c4) — this is the cascade: that code sequence is level 1's input. Level 1's encoder self-attends over c1..c4 the same way; since nothing sits above it, this is the genuinely autoregressive top. Level 1 also extracts one further code from itself (e) exactly like every other level does. Reading top to bottom: level 0's decoder gives each block a trainable seed/query token (Q1..Q4) that cross-attends first to that block's own code, then — chained one hop further — to level 1's own code e (track 1). Every code is embedded before it becomes cross-attention key/value — the decoder never reads a raw hidden state directly.

Figure B

ks221 — three levels

Same byte string, one more level of compression. Level 2 now reads level 1's own code as its input, and is the top. Level 0's decoder now chains two cross-attention tracks above its own code.

One more level, same grammar. Level 1 now sits in the middle: it self-attends over level 0's code (c1..c4), and its own extraction groups pairs of those into level 2's input (d1, d2). Level 2 is now the top. Level 0's decoder is unchanged in kind, just longer: the same seed/query tokens cross-attend first to their own code, then chain through two further tracks — level 1's own code, then level 2's own code — each one embedded before it reaches cross-attention, each stage's output feeding the next as its query.

extract code (encoder cascade, upward)

What's identical between the two figures: every level is trained the same way (self-attend, extract a code, and separately decode itself from that same code); a code is always embedded before it reaches any cross-attention, never handed over as a raw hidden state. What changes going from ks21 to ks221 is only how many coarser codes level 0's decoder chains through before producing its final byte predictions — one more level means one more track, staged after the ones already there, not a different mechanism.
